# Simple Profile App (Docker + Amazon S3)

A one-page app that:
- accepts a name and age and displays them on the same page (not saved to a database);
- previews an application logo and uploads it to an S3 bucket.

## 1. AWS setup

1. Create an S3 bucket in your preferred AWS Region (example: `ap-south-1`). Bucket names must be globally unique.
2. Keep **Block all public access** enabled. This app uploads privately; it does not make the logo public.
3. In the bucket's **Permissions → CORS**, add this configuration (replace only if you use another origin):
   ```json
   [
     {
       "AllowedHeaders": ["*"],
       "AllowedMethods": ["PUT"],
       "AllowedOrigins": ["http://localhost:3000", "http://YOUR_EC2_PUBLIC_DNS_OR_IP:3000"],
       "ExposeHeaders": ["ETag"],
       "MaxAgeSeconds": 3000
     }
   ]
   ```
4. Give the identity running the app permission to upload only into this bucket's `app-logos/` folder. Example IAM policy (replace the bucket name):
   ```json
   {
     "Version": "2012-10-17",
     "Statement": [{
       "Effect": "Allow",
       "Action": ["s3:PutObject"],
       "Resource": "arn:aws:s3:::YOUR_BUCKET_NAME/app-logos/*"
     }]
   }
   ```

## 2. Run locally with Docker

From this project folder:

```bash
docker build -t profile-s3-app .
docker run --rm -p 3000:3000 \
  -e AWS_REGION=ap-south-1 \
  -e S3_BUCKET=YOUR_BUCKET_NAME \
  -e AWS_ACCESS_KEY_ID=YOUR_ACCESS_KEY \
  -e AWS_SECRET_ACCESS_KEY=YOUR_SECRET_KEY \
  profile-s3-app
```

Open `http://localhost:3000`.

For local learning, the environment variables above can use an IAM user's access keys with the restricted policy. Never commit keys to GitHub or bake them into the Docker image. You can also use an AWS profile by mounting your local AWS config/credentials into the container.

## 3. Push source code to GitHub

Create an empty GitHub repository, then run:

```bash
git init
git add .
git commit -m "Build profile app with S3 logo upload"
git branch -M main
git remote add origin https://github.com/YOUR_GITHUB_USERNAME/YOUR_REPOSITORY.git
git push -u origin main
```

## 4. Push Docker image to Docker Hub

Create a Docker Hub repository, then:

```bash
docker login
docker build -t YOUR_DOCKERHUB_USERNAME/profile-s3-app:1.0 .
docker push YOUR_DOCKERHUB_USERNAME/profile-s3-app:1.0
```

Anyone with Docker can pull it:

```bash
docker pull YOUR_DOCKERHUB_USERNAME/profile-s3-app:1.0
```

## 5. Run on EC2

1. Launch an EC2 instance and install Docker.
2. Attach an **IAM role** to the instance with the restricted S3 `PutObject` policy above. Prefer an instance role; do not put AWS keys on EC2.
3. Ensure the EC2 security group allows inbound TCP port `3000` from your IP for testing.
4. On EC2, run:

```bash
docker pull YOUR_DOCKERHUB_USERNAME/profile-s3-app:1.0
docker run -d --name profile-app --restart unless-stopped \
  -p 3000:3000 \
  -e AWS_REGION=ap-south-1 \
  -e S3_BUCKET=YOUR_BUCKET_NAME \
  YOUR_DOCKERHUB_USERNAME/profile-s3-app:1.0
```

Open `http://YOUR_EC2_PUBLIC_IP:3000`.

## Notes

- The browser uploads directly to S3 using a short-lived presigned URL generated by the app server.
- The server needs AWS credentials from your local environment or the EC2 instance role.
- The name and age are displayed in the browser only. They are not stored.
- Uploaded objects remain private by default. To view/download one, use the S3 console or add a separate authenticated viewing feature.
- For a real public deployment, put the app behind HTTPS (for example, an Application Load Balancer) rather than exposing plain HTTP.
